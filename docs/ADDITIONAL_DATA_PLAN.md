# 추가 데이터 학습 계획

작성일: 2026-08-26
프로젝트 경로: `/Users/bangjiwon/dev/pigproject`

## 1. 왜 필요한가

현재 생체 에너지 LSTM이 실제로 보는 데이터는 650행(윈도우 380개, 학습 309 / 검증 71)뿐이고, 기간도 `2022-11-17~12월`(71408)과 `2023-08~09월`(71763) 두 덩어리로 끊겨 있다. 돈방별로도 19행(71408 chamber 3, 지금은 seq_len=24 미달로 학습에서 아예 제외)부터 188행(71763 chamber 1)까지 편차가 크다.

이 상태에서 나오는 문제:

- 검증 window 71개로 p99를 잡으면 사실상 "가장 크거나 두 번째로 큰 값"을 threshold로 쓰는 것과 같아 추정이 불안정하다.
- 지금까지 confirmed anomaly가 0개다. 즉 탐지기가 실제 이상을 잡아내는지 한 번도 검증된 적이 없다.
- 두 데이터 시기가 계절적으로 다르고(초겨울 vs 늦여름) 서로 다른 dataset_key에 갇혀 있어, 계절 효과와 진짜 이상 신호가 섞일 위험이 있다.
- 622(행동/키포인트) 트랙과 생체 에너지 트랙이 아직 결합되지 않았다.

## 2. 목표

1. 통계적으로 안정된 threshold를 낼 수 있을 만큼 검증 데이터 확충
2. 계절/기간 커버리지 확대
3. 돈방별 표본 불균형 완화
4. 탐지기가 실제 이상을 잡아내는지 검증 가능한 기반 마련
5. 622 트랙과 생체 에너지 트랙 결합 준비

## 3. 데이터 소스별 계획

### A. AI Hub 기존 데이터셋에서 더 받을 게 있는지 확인 (가장 저비용, 최우선)

지금까지 71408/71763은 각각 `TL.zip`(training 라벨) + `VL.zip`(validation 라벨)만 받았다. `config/aihub_datasets.json`의 `recommended_first_downloads`는 애초에 "스키마부터 검증하자"는 최소 셋이었지, AI Hub에 있는 전체 파일 목록이 아니다.

할 일:

```bash
export AIHUB_API_KEY="발급받은_키"
pig-aihub files --dataset-key 71408
pig-aihub files --dataset-key 71763
pig-aihub files --dataset-key 622
```

전체 파일 목록을 다시 조회해서 다음을 확인한다.

- TL/VL 라벨 외에 다른 chamber, 다른 기간을 담은 라벨 파일이 더 있는지
- 622는 지금 키포인트 라벨(15MB)만 받았고, `01.바운딩박스/TL01.zip`(148MB) 등 bbox 라벨은 아직 안 받았다 — 활동량 트랙 보강용으로 저비용 우선순위
- 이미지(원천) 파일은 여전히 후순위. 라벨/메타만으로 표본을 늘릴 수 있는지 먼저 확인한다.

### B. 시간 커버리지 확대

71408(초겨울)과 71763(늦여름) 사이에 큰 시간 공백이 있다. AI Hub에 더 긴 연속 기간 파일이 있으면 최우선으로 받고, 없다면 "이 데이터셋 자체의 근본적 한계"로 문서에 명시하고 실제 농장 데이터 확보가 필요하다는 결론으로 넘어간다.

### C. 탐지기 sanity check용 합성 이상 데이터 (다운로드 불필요, 즉시 실행 가능)

새 데이터를 기다릴 필요 없이 지금 바로 할 수 있다. 정상 검증 윈도우 일부를 인위적으로 변형해서 (체온 +3도, `distance`를 0 근처로, `breath_rate` 급증 등) 탐지기가 그걸 실제로 잡아내는지 확인한다.

```text
1. bioenergy_val_scaled.csv에서 window 몇 개를 복제
2. 복제본의 특정 피처 값을 크게 왜곡
3. 왜곡된 배열을 X_new로 pig-detect --input에 넣어 실행
4. raw_anomaly / confirmed_anomaly로 잡히는지 확인
```

이건 데이터 확보 계획과 독립적으로 가장 먼저 해볼 가치가 있다 — 지금까지 이 파이프라인이 "진짜 이상"을 한 번도 잡아본 적이 없기 때문이다.

### D. 돈방별 최소 표본 확보

71408 chamber 3(19행)은 지금 구조상 제외된다. 추가로 받을 수 있으면 최우선이고, 안 되면 `seq_len`을 그룹별로 다르게 적용할지(예: 짧은 그룹만 12로) 결정해야 한다.

## 4. 실행 순서 제안

1. **(지금 바로, 다운로드 불필요)** C — 합성 이상 주입 sanity check
2. `AIHUB_API_KEY` 설정 → A — `pig-aihub files`로 71408/71763/622 전체 목록 재조회
3. 추가 라벨 파일이 있으면 다운로드 → `pig-normalize` → `pig-validate-data`로 정규화/검증
4. 확장된 데이터로 `pig-build-bioenergy` → `pig-train` → `pig-threshold-compare` 재실행, 아래 목표 수치 도달 확인
5. 622 트랙도 같은 방식으로 기간/돈방 커버리지 재점검
6. 여기까지 끝나면 ensemble(생체 에너지 + 행동량) 설계 착수

## 5. 목표 수치 (제안 기준)

| 항목 | 현재 | 목표 |
|---|---:|---:|
| 전체 검증 window | 71개 | 300개 이상 |
| 돈방(dataset+chamber)당 학습 window | 최소 1개(짧은 그룹) | 50개 이상 |
| 돈방(dataset+chamber)당 검증 window | 최소 6개 | 20개 이상 |
| 시간 커버리지 | 계절 2개 조각(비연속) | 연속 6개월 이상 또는 계절 2개 이상 정식 커버 |

## 6. 리스크 / 주의

- **AI Hub에 실제로 더 받을 라벨이 없을 수 있다.** 이미 TL+VL을 다 받았을 가능성이 있다 — 이 경우 표본을 못 늘리는 게 데이터셋 자체의 근본적 제약이므로, threshold 산출 방식을 단순 percentile 대신 파라메트릭 분포 적합이나 부트스트랩 신뢰구간으로 바꾸는 방향을 검토해야 한다.
- **이미지까지 받으면 수십~수백GB 단위 스토리지/시간이 든다.** 라벨/스키마 검증 없이 먼저 받지 않는다(README/AIHUB_API_PLAN.md 원칙 유지).
- **돈방별 scaler의 cold-start 문제.** 지금은 돈방마다 scaler를 따로 학습하는데, 새 돈방/새 기간 데이터가 들어오면 그 돈방 전용 scaler가 아직 없다. 새 돈방 등장 시 임시로 전체 평균 scaler를 쓰다가 데이터가 쌓이면 전용 scaler로 전환하는 정책이 필요하다 — 지금 코드(`fit_scalers_per_chamber`)는 이 fallback이 없으므로 추가 구현이 필요하다.
